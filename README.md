## Структура и организация Data Lake

Для реализации проекта обновлена структура хранилища в HDFS. Данные организованы по слоям в соответствии с принципами построения масштабируемых озер данных.

### 1. Архитектура слоев данных

| Слой | Директория в HDFS | Описание | Формат |
| --- | --- | --- | --- |
| **Raw** | `/user/master/data/geo/events` | Исходные данные о событиях (сообщения, подписки и т.д.) с координатами. | `parquet` |
| **ODS** | `/user/null2de/data/geo/events` | Очищенные и типизированные данные, подготовленные для расчетов. | `parquet` |
| **Analytics** | `/user/null2de/data/analytics/` | Финальные витрины, готовые для использования аналитиками и BI-инструментами. | `parquet` |

### 2. Описание витрин (слой Analytics)

* **`users_geo`**: Базовая витрина с историей перемещений пользователей и их "домашним" городом.
* **`geo_activity_stats`**: Гео-аналитика активности в разрезе городов, недель и месяцев.
* **`friend_recommendations`**: Рекомендательная система для поиска друзей по близости координат и общим интересам.

### 3. Регламент обновления и форматы

* **Частота обновлений**: Ежедневно в **03:00 UTC** (согласно расписанию Airflow DAG). Данные обрабатываются в режиме Batch-процессинга.
* **Формат данных**: Все данные на всех этапах хранятся в формате **Parquet**. Это обеспечивает:
* Сжатие данных (экономия места в HDFS).
* Колоночное хранение (ускорение аналитических запросов, где не нужны все поля).
* Поддержку сложных схем данных (nested fields в событиях).


* **Тестирование**: Для отладки и тестирования новых скриптов используется временная директория `/user/null2de/data/test/`. Продакшн-данные в `/analytics/` перезаписываются в режиме `overwrite` только после успешного прохождения всех этапов DAG.
